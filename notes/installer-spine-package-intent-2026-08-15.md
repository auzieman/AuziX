# AUZiX installer spine package intent — 2026-08-15

Tonight's installer focus is the narrow install spine, not a fresh desktop
repair adventure.

## What changed

- `auzix-installer run PLAN` now passes the reviewed JSON plan to
  `/System/Tools/auzix-install-disk` as `AUZIX_INSTALL_PLAN`.
- `auzix-install-disk`, generated by `scripts/add-auzix-live-tools.sh`, now
  preserves that plan in the installed root:
  - `/System/Settings/install/install-plan.json`
  - `/System/Settings/packages/first-boot-selection.list`
  - `/System/Settings/packages/first-boot-queue.json`
- Package selections no longer block the guarded installer execution path.
  They are recorded as first-boot/hydration intent.
- Added `installer/plans/workstation-demo.json` as the current burrito-style
  workstation target: LightDM, Enlightenment, Xorg, browser, Flatpak, Podman,
  LibreOffice modules, editors, and Ephoto.

## Rule

The destructive disk-copy phase installs the base root and records intent. It
does not claim workstation packages were hydrated until the package tier runs
and validates them.

This keeps the install path honest:

1. base disk install,
2. installed-root sanity,
3. first-boot/package hydration queue,
4. desktop/app validation.
